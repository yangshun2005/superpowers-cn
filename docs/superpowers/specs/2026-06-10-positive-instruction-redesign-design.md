# 技能指导的正向指令重构 — 设计规范

**状态：** 提案（2026-06-09 SDD 评审派发工作的后续；按"一 PR 一问题"规则单独提 PR）
**驱动因素：** 2026-06-10 的实测证据表明，技能文案中部分否定式指令适得其反，另一些则有效——且这种差异可预测。

## 本规范所归纳的实测发现

2026-06-10 的微测试（opus，每种措辞 5 次重复，程序化评分；测试框架见下文）测量了指导措辞如何改变控制器所撰写的内容：

| 用例 | 措辞 | 结果 |
|---|---|---|
| 派发撰写（"不要复述简报"） | 禁止式 | **4.4** 个规范值被重新录入——*比无指导更差*（3.6） |
| 派发撰写 | 正向配方（"你的派发应包含：(1)…(5)"） | **3.0，零方差**——采纳 |
| 派发撰写 | 配方 + 细微差别条款（"只引用片段…"） | 3.8，噪声大——细微差别稀释了配方 |
| 测试重跑指令（"不要要求评审者重跑测试"） | 禁止式 | **0/5 违规**——效果良好（对照组：3/5） |
| 测试重跑指令 | 正向配方 | 0/5——持平，但更长 |

**原则**（用于对任何否定式指令分类）：

1. **绊线有效。** 针对具体 token 的短语级自检（"如果你正在写的提示词包含'do not flag'……停下"）能可靠触发。
2. **识别表有效。** 红旗/合理化表在决策时阅读，而非撰写时。
3. **离散指令式禁止有效。** 当模型没有做 Y 的竞争性动机时，"不要要求 X 做 Y"成立。
4. **撰写式禁止会适得其反**——当模型对输出有自己的议程时（例如，复述规范感觉像是有用的整理）。只有正向撰写配方能改变这类情况——而给获胜配方添加细微差别条款会让它更糟，而非更好。
5. **平局取更短措辞。** Codex 在长会话中重读 SKILL.md 约 500 次（2026-06-10 实测）；文案长度是真实成本。

## writing-plans 变更（推迟项 #5）

### 当前状态

`skills/writing-plans/SKILL.md`，"No Placeholders"：一句正向陈述（"每一步都必须包含工程师所需的实际内容"），后跟一个六条禁用模式列表（"绝不写它们：'TBD'、'TODO'、'Add appropriate error handling'、'Write tests for the above'、'Similar to Task N'……"）。

### 为何重要以及为何确实不确定

- 计划是工作流中**最大的生成产物**，且模型有真实的竞争性动机去输出占位符（在长度压力下它们是最省力的路径）——这正是禁止可测量地适得其反的情形。
- 但被禁项是**离散、可识别的 token**——这正是禁止可测量地成立的情形。
- **该列表在其他地方承重：** 该技能的 Self-Review 部分引用了它（"占位符扫描：在你的计划中搜索红旗——上述'No Placeholders'部分中的任何模式"）。这些 token 同时充当评审时的扫描清单，而评审时识别正是有效的类别。简单换成正向清单会破坏该引用，并丢弃良好的绊线 token。

### 待测试的变体

- **V0（当前）：** 撰写时正向陈述 + 禁用列表；Self-Review 引用该列表。
- **V1（审计者清单）：** 仅撰写时正向配方——"在最终确定一步之前，确认它包含：要写的字面代码、带预期输出的可运行命令、本计划内定义的类型和方法名、显式展示的错误处理。当工程师无需任何后续提问即可实现时，该步才算完成。"Self-Review 保留通用占位符扫描。
- **V2（按机制重构——预测胜出）：** 撰写时只保留 V1 的正向配方；具名模式整体移入 Self-Review 占位符扫描步骤，重新表述为识别（"扫描时，查找：'TBD'、'TODO'、'Similar to Task N'……"）。相同 token，从引发类别迁移到检测类别。
- **V3（对照）：** 仅正向陈述，任何地方都无列表。

### 微测试设计

- **任务：** opus 从一个刻意欠规范的规范中写一份 2-3 任务的实现计划（欠规范正是诱发占位符的原因）。使用一个夹具规范，包含：一个规范良好的任务、一个规范对错误处理含糊其辞的任务、一个与第一个相似的任务（诱发"Similar to Task 1"）。
- **采样：** 每变体 5+ 次重复，默认温度，模型 `claude-opus-4-8`（实践中写计划的模型）。
- **程序化评分**（除非注明，越低越好）：
  - 禁用 token 计数：`TBD|TODO|implement later|fill in details|appropriate error handling|handle edge cases|Similar to Task|Write tests for the above`
  - 在步骤修改代码处缺少围栏代码块的步骤
  - 引用计划输出中任何地方都未定义的类型/函数
  - （越高越好）每个任务带预期输出的可运行命令
- **V2 的两阶段评分：** 同时测试 Self-Review 半部分——将每份生成的计划连同该变体的 Self-Review 部分回馈，测量扫描是否真正捕获植入的占位符（向夹具计划中插入 2 个已知占位符；检测率即指标）。
- **验收：** 仅当某变体在禁用 token 计数上胜过 V0，且不损失代码块覆盖率或自评审检测率时才采纳。预期成本：总计约 $6-10。

### PR 范围

单独 PR（writing-plans 是不同技能；其"No Placeholders"列表是调优内容，贡献者指南要求评估证据）。该 PR 必须包含：微测试框架 + 结果表、前后文本，以及 V2 迁移理由。

## 微测试框架（方法，以免丢失）

`/tmp/sdd-exp/micro/run-micro.py` 和 `/tmp/sdd-exp/micro2/run-micro2.py`（2026-06-10；将提交至 superpowers-evals，作为 `docs/superpowers/skills/micro-testing-prompt-guidance.md` + 脚本）：

- 每样本一次 API 调用：系统提示词 = 置于真实周围上下文中的技能指导变体；用户 = 真实的工作流中场景；输出 = 撰写的产物（派发提示词、计划、报告）。
- 用 grep 对无歧义标记进行程序化评分；**在信任任何判定之前手动检查每个匹配**——今晚的某个"违规"是控制器正确地引用了禁止条款，而自动否定检测又将另一个误标。
- 约 $0.15-0.30/样本，每次迭代数秒，对比 $12/50 分钟的全量评估运行。在此迭代措辞；仅当变更是结构性的时候才在全量运行中确认胜出者。
- 始终包含无指导对照——今晚它既揭示了一个适得其反（复述：禁止比无指导更差），也揭示了一个有效的禁止（测试重跑：对照组 3/5 失败 vs 任一措辞 0/5）。

## 结果：writing-plans 微测试（2026-06-10 运行，本规范写就之后）

**已解决——无需变更。** 阶段 1（3 任务规范，无压力）：全部四个变体（包括无指导对照）的 20 份计划中 0 占位符。阶段 1b（10 任务规范，五个近乎相同的命令诱发"Similar to Task N"，明确的约 2,500 词经济性目标）：40/40 干净——唯一一次正则命中是 V2 自评审*证明*"无 TBD/TODO ✓"。当前代 opus 即使在刻意压力下也不产生计划占位符，无论有无禁用模式列表。处置：No Placeholders 部分完全保持原样（成本很小，反事实不可测量）；不要开后续 PR。V2 迁移设计留档于此，以备未来模型代际回退。

## 同样明确未丢弃（已测试并拒绝，附数据）

记录于此，以免有人在没有新证据的情况下重新提议——完整数字见 2026-06-09 SDD 设计规范的 Cost-iterations 部分：

- **控制器轮次批处理 / 单消息并行工具调用：** 控制器每条消息恰好发出一次工具调用（在所有测量运行中，无论有无指导，0 条多工具消息）。46% 的控制器轮次是无工具调用的思考/叙述——提示词无法改变的下限。
- **通过并行调用实现流水线评审：** 出于同样原因不可行。
- **通过 `run_in_background` 实现流水线评审：** 提供时机制被采纳（7/28 次派发），但在 45 分钟场景中收益低于运行间噪声下限（每次评审仅约 30-60 秒）；增加了双结果流协调。仅对评审各自很长的计划值得重新考虑。
- **追加到获胜配方的细微差别条款：** 可测量地使其退化（C2：3.8 噪声大 vs C：3.0 一致）。通过重新推导配方来迭代，而非追加告诫。
