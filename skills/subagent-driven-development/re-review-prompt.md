# 限定范围复审提示词模板

修复轮次结束后派发复审时使用本模板。复审者核实各项发现是否已处理，并检查修复 diff 是否引入新问题。这不是全新审查——完整审查已经做过。

**目的：** 核实上一轮审查的每项发现均已处理，且修复本身未破坏任何东西。

```
Subagent (general-purpose):
  description: "Re-review Task N fix round R"
  model: [MODEL — 必填：按 SKILL.md 的 Model Selection 选择；省略
         model 会静默继承会话中最贵的模型]
  prompt: |
    你正在复审一个任务的修复轮次。上一轮审查产出了若干发现；实现者
    已尝试修复。你的工作是逐项裁定每个发现并检查修复 diff——仅此而已。

    ## 任务

    阅读任务简报：[BRIEF_FILE]

    ## 待核实的发现

    [FINDINGS]

    ## 修复

    阅读实现者的报告（修复报告追加在末尾）：
    [REPORT_FILE]

    **修复基线：** [FIX_BASE_SHA]（上一轮审查看到的 head）
    **Head：** [HEAD_SHA]
    **Diff 文件：** [DIFF_FILE]

    只读一次 diff 文件——其中包含修复提交、统计摘要，以及带上下文的
    修复 diff。不要重复运行 git 命令。若 diff 文件缺失，自行获取：
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` 和
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    本次审查对此检出只读。不得以任何方式改动工作区、索引、HEAD 或
    分支状态。

    ## 你不得派发子代理

    全部审查由你亲自完成。绝不要派子代理审查部分 diff，也绝不要派
    另一个审查者寻求第二意见。本流程已为工作提供全部审查席位；你
    派出的审查者只是以全价重复其中一个席位，其裁定不作数。若 diff
    大到一次读不完，就自己分多次审查，并在报告中说明。

    ## 范围

    你的范围是发现列表和修复 diff。逐项裁定每个发现。检查修复 diff
    是否引入新问题。不要复审修复未触及的代码：若你发现的问题完全
    在修复 diff 之外，写入"范围外观察"——它不阻塞本任务，也不延长
    循环。所有任务完成后会做一次全分支审查。

    ## 测试

    实现者已重跑覆盖修改代码的测试，并将结果追加到报告文件。把报告
    视为未经核实的声明：确认修复报告列出了覆盖测试并展示了输出，并
    对照 diff 核实这些声明。不要重跑测试套件来确认其报告。仅当阅读
    代码产生现有运行无法回答的具体疑问时才运行测试——且只跑聚焦
    测试，绝不跑整个包的测试套件。

    ## 输出格式

    你的最终消息就是报告本身：直接从第一个发现的裁定开始。每一行
    要么是裁定、要么是带 file:line 的发现、要么是你执行的检查——
    不要开场白，不要过程叙述。

    ### 发现裁定

    按顺序对"待核实的发现"中的每一项：
    - **[发现一句话摘要]** — ADDRESSED | NOT ADDRESSED，附 file:line
      证据。"已尝试"不算已处理：具体缺陷必须不再存在。

    ### 修复 diff 中的新破坏

    修复本身破坏或引入的任何问题，附严重程度
    （Critical/Important/Minor）和 file:line。若无则写"None"。

    ### 范围外观察

    你发现的完全在修复 diff 之外的问题。不阻塞；控制器会记录这些
    供最终审查。若无则写"None"。

    ### 裁定

    **修复轮次：** [所有发现均已处理，无新的 Critical/Important
    破坏 | 仍有发现未关闭] — 列出未关闭项。
```

**占位符：**
- `[MODEL]` — 必填：按 SKILL.md 的 Model Selection 选择审查者模型；小修复 diff 的限定范围复审用低到中档
- `[BRIEF_FILE]` — 任务简报文件（实现者工作时所用的同一文件）
- `[FINDINGS]` — 上一轮审查中的 Critical/Important 发现和规格缺口，逐字复制，每条一项
- `[REPORT_FILE]` — 实现者的报告文件（修复报告追加于此）
- `[FIX_BASE_SHA]` — 上一轮审查看到的 head
- `[HEAD_SHA]` — 当前提交
- `[DIFF_FILE]` — `bash scripts/review-package PLAN_FILE FIX_BASE HEAD` 打印的路径

**复审者返回：** 逐项发现裁定（ADDRESSED / NOT ADDRESSED）、修复 diff 中的新破坏、范围外观察，以及轮次裁定。
