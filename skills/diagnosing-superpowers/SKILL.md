# 诊断 Superpowers

## 概述

与你的搭档一起确定会话中出了什么问题，读取磁盘上的转录记录，并带证据报告发生了什么。你只报告，不诊断 superpowers。由分诊该包或 Issue 的人决定 superpowers 是否修改。

**核心原则：** 每条发现都引用 `path:line`。无引用，无发现。每个数字都来自转录记录或你运行过的命令，绝不来自记忆。

## 工作流

每步创建一个待办。步骤 5–7 仅在其所述条件下运行。

1. **问题收集。** 一次问一个问题，直到你能写出一段陈述，指明会话、已知的轮次范围、搭档的预期、实际发生的情况，以及他们关心的可观测指标（实际耗时、token、重复动作、某个具体动作）。"耗时太长"是抱怨，不是问题陈述。记录目标是否为 superpowers 缺陷报告。
2. **定位。** 使用 `references/session-discovery.md` 将每个会话解析为已验证的绝对文件系统路径。通过引用首个提示和时间戳确认过往会话，并列出你拒绝的每个候选及原因，或"无"。枚举子代理转录记录。创建 `~/.superpowers/diagnosing-superpowers/<session-id>/`，告知搭档该路径，并在其中填写 `templates/case.md`，遵循其关于环境和技能观察的来源规则。
3. **分诊。** 亲自阅读所报告问题附近的区域。然后按维度并行派发分析子代理，每个获得案例文件路径、`prompts/analyst-common.md`，以及 `prompts/` 中的一个维度文件：`skill-timeline.md`、`plan-adherence.md`、`repeated-work.md`、`stumbles.md`、`quality-evidence.md`、`request-conflicts.md`、`cost-and-time.md`。转录记录较长时按轮次范围拆分维度。丢弃任何没有 `path:line` 的返回发现。
4. **报告。** 按顺序填写 `templates/report.md` 的每一节，写入工作区，展示它，并给出路径。检查所引用内容实际证明了什么，并保留支撑案例；符号链接别名不是冗余副本。
5. **GitHub Issue**——当报告 §7 说可能或很可能，或搭档要求时。按 `references/github-issues.md` 搜索开放和已关闭 Issue 中的症状。展示匹配项并建议将报告添加到最接近的 Issue。若无匹配，填写 `templates/issue.md`，写入工作区，展示确切文本，仅在批准后创建 Issue。`gh` 无法附加文件；若存在包，将路径给搭档以便在浏览器中附加。
6. **导出**——仅在搭档要求包时；绝不主动构建。若收集目标为缺陷报告，说一次可按需提供已脱敏的包，然后等待。询问脱敏级别，说明各自包含什么：骨架（无工具结果正文）、证据（仅引用事件的正文）、完整。按 `templates/bundle-README.md` 构建包，派发 `prompts/scrub.md`，然后 `prompts/scrub-audit.md`，重复两者直到审计返回 CLEAN。在展示最终脱敏日志、文件列表以及隐私和证据结果之前，完成包模板的证据检查和核对。仅在批准后归档（`zip -r` 或 `tar -czf`）。给出归档路径时，说明其内容，指向脱敏日志以查看替换项，并说明脱敏可能遗漏内容：分享前必须审查每个文件。
7. **相似会话**——被要求时。将确认的发现转化为签名，按 mtime 和大小列出候选，找到标记行号，按候选并行派发 `prompts/similar-session.md`，并追加报告 §9。

## 快速参考

七个分析器始终全部运行。此表说明步骤 3 中你亲自阅读哪个区域，以及裁决中先呈现哪些发现。

| 抱怨 | 先读，先呈现 |
|---|---|
| "耗时太长" | cost-and-time、stumbles |
| "为什么做这些额外工作？" | repeated-work、plan-adherence |
| "为什么这么贵？" | cost-and-time |
| "它到底在干什么？"（仍在运行） | skill-timeline；在覆盖范围中注明进行中 |
| "它无视了计划" | plan-adherence，先看压缩行 |
| "技能 X 从未触发" | skill-timeline |

## 硬性规则

- **上下文安全。** 一行转录记录可能有一兆字节。每次对每个会话文件都遵循 `references/context-safety.md`。
- **只读。** 绝不修改、移动或删除会话文件。
- **给子代理精确路径。** 子代理的"当前会话"是它自己的。传递绝对路径和 id。
- **仅人类提示。** Hook 输出、系统提醒和工具结果不是搭档的话。在子代理转录记录中，"user"是父代理。
- **不做 superpowers 诊断。** 报告 §7 陈述涉及情况后即停止。绝不在技能中命名缺陷或提出修改。搭档施压要求修复也不豁免此条；指向 Issue 步骤并提及可按需提供包。也不给搭档建议。
- **批准关卡。** 搭档看到脱敏日志和文件列表前不归档。他们批准确切文本前不创建 Issue 或评论，且不得带占位摘要。
- **先收集后分析。** 搭档回答前，步骤 2–7 不开始。若他们不在，写下问题并停止。你为他们重建的陈述不是回答。已明确范围的请求——某个具体事件、当前运行的内容、或要运行的分析——本身就是陈述：回答它，然后提问。整个会话的"为什么"是抱怨。

## 危险信号

| 想法 | 现实 |
|---------|---------|
| "问题很明显，跳过收集" | 问题陈述界定一切。要问。 |
| "他们不在，我来重建陈述" | 你无法重建他们想要什么。写下问题并停止。 |
| "我现在全面扫描，最后再问" | 无范围扫描把他们的预算花在错误问题上。先问。 |
| "他们想要缺陷报告，所以我现在构建包" | 包是他们的会话数据打包。仅在他们要求时构建。 |
| "小范围针对性修改，无需重构" | 无论多小，不由你决定。报告证据；分诊者决定。 |
| "每 token 价格众所周知" | 你未从转录记录计算的数字是编造的。引用或丢弃。 |
