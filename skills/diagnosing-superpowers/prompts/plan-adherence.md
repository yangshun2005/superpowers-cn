维度：计划遵循度

还原会话中各方达成一致的计划，再把每个计划步骤对应到实际发生的事。这里的“计划”指任何达成一致的行动方案，不限于 git 提交。

1. 找出达成一致的计划：聊天中商定的设计或计划（找人类说“yes/ok/go ahead”之前的助手文本）、会话期间写下的规格或计划文件（在 `docs/`、`plans/`、`specs/` 下写入的工具调用，或人类点名的任何文件）、含义已在案卷中确立的待办清单记录，或助手文本中的任何编号清单。引用每个计划步骤及其 `path:line`。
2. 标出计划与执行之间的结构性事件：发现阶段识别出的压缩事件、恢复、中止的轮次，以及相关的会话派发。记下其行号；紧接这类事件之后的计划偏移是独立发现。
3. 对每个计划步骤，找出执行它的工具调用和助手文本，或确认没有任何执行。报告：
   - 跳过的步骤（未找到执行；引用该计划步骤）；
   - 乱序执行的步骤（行号显示顺序）；
   - 静默变更的步骤（执行与计划步骤的差异是助手从未声明的；引用两者）；
   - 凭空发明的步骤（做了没有任何计划步骤覆盖的工作）；
   - 结构性事件后立即出现的偏移（引用事件行号和第一个偏离动作）。
4. 如果没有可还原的计划，将其作为唯一发现说明，并列出你检查过的行。
