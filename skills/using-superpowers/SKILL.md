## 规则

**在任何响应或行动之前调用相关或被请求的技能**——包括澄清问题、探索代码库或检查文件。如果发现不适用于当前情况，你不必使用它。

**进入计划模式之前：** 如果你尚未进行头脑风暴，先调用头脑风暴技能。

然后声明"使用 [技能] 来 [目的]"并严格遵循该技能。如果它有检查清单，为每一项创建待办。

## 技能优先级

多个技能适用时，流程技能优先——它们确定方法，然后由实现技能（frontend-design 等）执行。头脑风暴和系统化调试是 Superpowers 最常用的流程技能，但该规则适用于任何流程技能。

- "我们来构建 X" → 先 superpowers:brainstorming，再实现技能。
- "修复这个 bug" → 先 superpowers:systematic-debugging，再领域技能。

## 危险信号

以下想法意味着停下——你在找理由：

| 想法 | 现实 |
|---------|---------|
| "这只是个简单问题" | 问题就是任务。检查技能。 |
| "我需要先了解更多上下文" | 技能检查在澄清问题之前。 |
| "让我先探索代码库" | 技能告诉你如何探索。先检查。 |
| "我可以快速查看 git/文件" | 文件缺乏对话上下文。检查技能。 |
| "让我先收集信息" | 技能告诉你如何收集信息。 |
| "这不需要正式技能" | 如果技能存在，就用它。 |
| "我记得这个技能" | 技能会演进。阅读当前版本。 |
| "这不算任务" | 行动 = 任务。检查技能。 |
| "这个技能太重了" | 简单的事会变复杂。用它。 |
| "我先只做这一件事" | 做任何事之前先检查。 |
| "这感觉很有成效" | 无纪律的行动浪费时间。技能可防止这一点。 |
| "我知道那是什么意思" | 知道概念 ≠ 使用技能。调用它。 |
